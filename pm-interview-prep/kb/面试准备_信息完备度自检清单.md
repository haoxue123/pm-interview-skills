# 面试准备 · 信息完备度自检清单（反脆弱前置）

> **来源**：2026-08-04 第一性原理分析 + 全民K歌一面失败复盘反哺。
> **用途**：每次 T9 面试前准备，第一步不是调研、不是押面型，而是先列「已知 / 未知」+ 让用户补最高边际价值的信息。这是 skill v0.14「反脆弱默认」的落地载体。
> **定位**：本清单 = T9 流程的**步骤 0（前置）**，必须在企业调研之前走。

---

## 一、为什么需要这个清单（第一性原理）

面试准备的本质 = **不确定性下的预测问题**。

> 准备准确度 = f(输入信息质量, 推理 / 建模质量, 内在不确定性)

- **内在不确定性**（面型、面试官关注点、具体题目）是方差主源，**事前基本不可知**。
- 全民K歌翻车根因：把「产品策划实习」误读成「广告策划岗」+ 按广告专业题清单押题 → 真实面型（开放题思维面）完全错配，专业准备全盘落空。
- **关键结论**：面型这个变量，对你和我**事前都不可知**（没人告诉你"不聊实习"）。所以它不是"你该补但没补的信息"，而是"任何人事前都补不了"的变量。
- 因此正确解法 = **让准备反脆弱**（押能力结构不押面型），而不是"多收集信息就能解决"。但"能补的信息"里，确实有几项能显著降低不确定性——下面排名。

---

## 二、已知 / 未知 模板（准备起步先填）

| 维度 | 已知（用户已给） | 未知（待补 / 不可知） |
|---|---|---|
| 岗位 JD | ___ | ___ |
| 公司 / 业务 | ___ | ___ |
| 面试轮次与形式 | ___ | ___ |
| 面试官身份 | ___ | ___ |
| **面型（最关键的不可知项）** | ___（通常未知） | 开放题 / 专业深挖 / HR 行为 / 带教面？ |
| 往届面经 | ___ | ___ |

> 填完这张表，再决定是否要追问用户补信息；面型那一行几乎永远标"未知"，这是常态，不是你漏了。

---

## 三、用户可补信息 · 边际价值排名（直接回答"该给 AI 什么"）

按"对准备内容的边际贡献"排序，不是按"你容易想到的"排序：

| 排名 | 信息 | 边际价值 | 说明 |
|---|---|---|---|
| 1 | 同类 / 同公司**往届面经** | ★★★★★ | 捕获"开放题思维面"等面型规律最高效；全民K歌若有面经即可避坑 |
| 1 | 面试**轮次 + 每轮形式 + 谁面** | ★★★★★ | 知道"一面开放题不聊实习"直接避开面型误判 |
| 2 | **面试官**身份 / 背景（**须可核实**） | ★★★★（**但置信度低**） | 钛动案例：用户口述"年幼带教/only one"实际是双面试官资深 PM——**HR/用户口头声称的面试官信息常失真，不能覆盖反脆弱默认**，必须以"可核实"（面试官当场自述 / 往届面经确认）为准 |
| 2 | 面试**岗位** JD | ★★★★（基线） | 通常已提供，是准备地基 |
| 3 | 面试**工作 / 业务**（团队痛点、当前项目） | ★★★☆ | 提升 F（业务了解）精度，知道真实痛点才能对齐 |
| 末 | 面试**时间** | ★☆☆☆☆ | 只影响稳定性话术 / 排期，**不改变"准备什么"**，边际最低 |

> 用户直觉常把"时间"排前面，但第一性原理看，时间对准备内容的边际贡献最小。轮次 / 形式 / 面试官 / 面经才最值得补。
> **⚠️ 面试官信息置信度警告（2026-08-04 钛动复盘）**：面试官身份 / 轮次 / 面型若来自"用户转述 HR 口头说法"，属**低置信**，可能失真（钛动即反例）。这类信息**只能作为增量、不能覆盖反脆弱默认**；若它与 JD / 薪资信号矛盾（如实习生 200–250/天却称资深带教、或"only one"实际双面试官），必须向用户提示二次确认，或直接按"能力结构通用包"准备。

### 三·0 主体辨识（排在最前，2026-09-10 爱莫科技踩坑新增）
**公司主体错 = 企业速览 / 五段式业务讲解 / AI 业务认知（防火墙 #7）/ JD 兑付矩阵整段作废。这是 T9 里最贵的单点错误，必须在任何检索之前解决。**

- **坑的形态**：招聘平台上的公司显示名常与工商全称差一字，且同音/近形主体可能同时存在 3–4 家，业务完全不同。实例：BOSS 显示「深圳**爱慕**科技有限公司」，实为「深圳**爱莫**科技有限公司」（AiMall，官网 mall-ai.com）；同期公开渠道还有「深圳市爱慕科技」（品牌电商）、「深圳爱幕科技」（AR/VR 硬件）、「爱慕生活科技（深圳）」（女性品牌）。
- **危险信号**：地区、行业标签、规模这几项"看着能对上"——因为近似主体的注册地往往也在同一个科技园。**这类弱信号不足以定主体。**
- **硬规则**：一旦发现公司名存在同名 / 近名歧义，**立即停止用"地区 + 行业标签 + 规模"推断，直接向用户索取官网链接或工商信息页面**；拿到后先做一次自洽校验——"它的业务描述 ↔ JD 岗位职责"能不能对上，再开始调研。
- **前置位置**：主体辨识属"准备地基的地基"，与本节信息完备度自检同层，**早于企业调研、早于读库**。

## 四、面经主动采集（强制动作 · 押面型前必问）

在 T9 押任何面型之前，**必须先问用户一句话**：

> 「这个岗位 / 这家公司，你有同类或同公司往届的面经吗？比如别人面过说什么风格、考不考实习、是不是开放题？」

- 若用户有面经 → 优先用面经定面型，**不押题**。
- 若用户没有 → 明确标记"面型未知"，进入**反脆弱默认**（见下）。

---

## 五、反脆弱默认决策规则

- **面型已知**（有面经 / HR 明说 / 往届确认）→ 按该面型专项包准备。
- **面型未知**（绝大多数情况）→ **默认出"能力结构通用包"**，而非"预测面型专项包"：
- **⚠️ 用户 / HR 口述前提不能覆盖本默认（2026-08-04 钛动复盘硬性规则）**：即便用户说"面试官是 X、只有一轮、是带教"，只要该信息来自口头转述（非面试官当场自述 / 非往届面经确认），准备稿就**仍须先出通用包打底**，把用户口述当"可能的增量"而非"锁死依据"。本次正是因被"年幼带教/only one"前提覆盖、未守通用包，导致整份准备面型误判。通用包内容见下。
  - 项目指标闭卷（B 维度，秒答项）
  - 答题引导 OP 三件套（边界 / 意图 / 数据优先于感受）
  - 4 种面型的"通用开场 + 转向剧本"（见 `kb/面型库.md`）
  - 用户视角案例库（开放题思维面保命包）
  - 稳定性 / 动机话术（HR / 带教面保命包）
- 反脆弱包的特征：**无论面型怎么变，这些都能直接用**，不会像全民K歌那样"专业准备全盘落空"。
