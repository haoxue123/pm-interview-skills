## 1. 核心原理（面试 = 5 面串联）

外部经验把一次面试拆成 **自我介绍 → 简历项目面 → 业务面 → 行为面 → 反问**，与本知识库 5 维度对应关系：

| 外部经验面 | 本知识库维度 | 关键信号 |
|---|---|---|
| 自我介绍 | 动机匹配 + 学习能力 | 是否理解岗位、能否把经历与岗位连接 |
| 简历项目面 | 项目真实性 + 产品思维 | 自圆其说、数据口径、决策深度 |
| 业务面 | 产品思维 + 逻辑表达 | 结构框架、事实口径、开放题拆解 |
| 行为面 | 动机匹配 + 学习能力 | 自我认知、真诚、成长曲线 |
| 反问 | 动机匹配 | 是否提前做功课、对岗位/团队/路径有真实思考 |

## 2. 可复用模块（模式层）

### M1 定向自我介绍钩子
- **原理**：自我介绍不是简历复读，而是**把岗位JD / HR沟通 / 公开信息**先压缩成「岗位理解」，再用自己的经历去「证明匹配」。
- **模式**：1.5 分钟版 = 个人信息 + 目标岗位/业务理解 + 3 个匹配特质（每个附一个 case）。
- **反模式**：通用版本流水账读简历；定向版本变成JD复述，没有自己的 case。
- **与本库衔接**：补强原有「展现态心法」——自我介绍也要场景化、具体化。

### M2 简历八大维度法（项目深挖标准答案）
- **原理**：面试官对项目的追问可以收敛到 8 个稳定维度，提前按这 8 维准备，就能覆盖 70% 简历面问题。
- **8 维**：背景 → 目标 → 动作 → 结果 → 指标 → 最大难点 → 权衡与取舍 → 再来一次怎么更好。
- **模式**：每个项目讲一个 20–30 秒的业务场景，再按 8 维展开；每个维度都有「why + what + how」的闭环。
- **反模式**：只说做了什么（what），不讲为什么（why）和怎么做决策（how）；指标口径答不上来。
- **与本库衔接**：直接补强用户 A 风险（决策深度）和 B 风险（数据口径）。

### M3 业务链路拆解法
- **原理**：开放业务题 = 用**结构**把模糊问题切到可分析单元，而不是凭直觉给方案。
- **模式**：按链路（拉新 / 促活 / 留存 / 转化 / 自传播）或视角（用户 / 平台 / 商业）或阶段（事前 / 事中 / 事后）三选一，先框范围再下结论。
- **反模式**：80–90% 时间准备业务面；但其实业务面只占面试 20–30%，投入产出比失衡。
- **与本库衔接**：强化原有「框架先行法」+「五层拆透法」。

### M4 过程指标异动拆解法
- **原理**：数据类问题（如 GMV 下降 30%）的考察点不是答案，而是**拆解路径是否完整、是否先确认真问题**。
- **模式**：
  1. 先确认是**真问题**还是噪声（周期/异常/口径变化）；
  2. 拆公式：GMV = 流量 × CTR × CVR × ARPU 等；
  3. 看分子/分母、同比/环比、实际数值；
  4. 给出两个归因方向：是「来的人少了」还是「买的人少了」等。
- **反模式**：直接给原因，不做公式拆解；用「感觉」「可能」代替口径。
- **与本库衔接**：补强原有「数据口径五要素」，增加「异动拆解四步」。

### M5 决策固定句式法（局部最优解表达）
- **原理**：所有「为什么这样做」「有没有更好的方案」本质在考**判断力/决策力**，而不是真有唯一最优解。
- **模式**：固定句式 = **「在 xx 场景下，由于 xx 资源限制和 xx 目标限制，所以 xx 方案更优」**。先讲约束，再讲选择，体现 trade-off 意识。
- **反模式**：说「这是老板定的」「资源不够」「只能这样」——把决策归因于外部，显得自己没有判断。
- **与本库衔接**：补强用户 C/D 风险（逻辑散/官方）——用这个句式把发散回答压回结构。

### M6 最大难点 / Plan C 法
- **原理**：最大难点通常只有两类——**资源不足**或**目标未对齐**。面试官想看你如何在约束下找双赢解。
- **模式**：优先讲 **Plan C**（同时达成双方目标），其次讲**安协轮次**（分阶段妥协），尽量不讲「找老板上升」。
- **反模式**：把难点讲成诉苦（资源不够、对方不配合），没有体现自己的推动策略。
- **与本库衔接**：补强用户 A 风险（决策深度）和项目真实性。

---

## 3. 反模式（ BAD 行为清单）

1. **不要讲「老板上升 / 资源不够」**：可以承认约束，但落脚点必须是「我在约束下做了什么选择」。
2. **不要只背逐字稿**：面试 80% 靠思路，20% 靠表达。准备「思路卡片」比「逐字稿」更抗追问。
3. **不要默认面试官懂业务**：每个项目先用 20–30 秒讲业务场景，再展开细节。
4. **不要用 80–90% 时间准备业务面**：业务面通常只占 20–30%，简历面和行为面才是大头。

---

## 4. 对用户的直接建议（映射到 A–F 风险）

- **A 决策深度**：用「简历八大维度法」重新整理你的字节/百度/作业帮三段经历，每个项目补出「最大难点 + 权衡与取舍 + 再来一次怎么更好」。
- **B 数据口径**：用「过程指标异动拆解法」把简历里的 CTR/ROI/GMV 数字做成「公式拆解 + 口径卡片」。
- **C 逻辑散 / D 官方**：用「决策固定句式法」把每个开放题/ why 题的回答压到「约束 → 选择 → 结果」三段。
- **F 业务了解不足**：自我介绍用「定向版本」——先输出对目标公司业务/岗位的理解，再连接经历。
