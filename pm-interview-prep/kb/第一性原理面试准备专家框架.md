# 第一性原理面试准备专家框架（岗位无关版）

> **定位**：一份不依赖任何具体公司 / 岗位 / 行业的面试准备元框架。  
> 它的作用是——当你拿到任意一份 JD、参加任意一场面试、读到任意一份经验库时，都能用同一套逻辑把信息变成**可复用的能力结构**，而不是背一堆用不上的题。  
> **状态**：v1.0（框架内核）；随真实面试记录与经验库持续反哺迭代。  
> **生成时间**：2026-07-26

---

## 0. 这个框架是什么 / 不是什么

- **是**：一套「信号提取 → 结构沉淀 → 可成长」的方法论。它告诉你面试在考什么、怎么拆解未知题、怎么把每次经历变成资产。
- **不是**：押题库、话术模板、标准答案合集。凡是「背这道题就能过」的思路，都和本框架冲突（见 §7 防火墙）。

**使用前提**：你愿意把每次面试当成数据来对待（记录 → 萃取 → 归纳），而不是当成一次性的考试。

---

## 1. 第一性原理起点：面试到底在考什么

### 1.1 面试是一个「信号提取」问题

面试官只有 30–45 分钟，看不到你真实的工作产出。他/她必须靠有限交互，从你身上提取 5 个关键信号，来判断「要不要你」。

> **推论**：面试官不关心你「答对了没有」，而关心——① 你这话是不是真的（ authenticity ）；② 你思考的方式像不像个产品人（ thinking ）；③ 你沟通清不清楚（ communication ）；④ 你是不是真想要这岗（ motivation ）；⑤ 你值不值得培养（ potential ）。

### 1.2 五个真信号（5 维度，不变骨架）

| 维度 | 面试官真正验证什么 | 失败信号 |
|------|-------------------|----------|
| **① 项目真实性** | 你简历上的事是不是真做过、贡献边界清不清楚 | 答泛、讲不清自己做了什么决策、数据经不起追问 |
| **② 产品思维** | 你会不会用产品视角看问题（用户 / 场景 / 设计意图） | 只说"好不好用"不说"为什么"；回答无结构 |
| **③ 逻辑与表达** | 压力下能不能把复杂的事讲清楚 | 语速快、串、无结构、念稿 |
| **④ 动机与匹配** | 为什么来、能不能留、跟岗位契不契合 | 动机模糊、说"都行"、对业务不了解 |
| **⑤ 学习能力与潜力** | 是不是可培养、对新事物敏不敏感 | 只会执行不会思考、对 AI/新工具无感 |

### 1.3 为什么「押题必败」

- 题目是**无穷**的，且每次换面试官、换赛道、换心情都会变；
- 你押中的题，面试官换种问法你就懵（因为他考的不是题，是维度）；
- 更危险的是：押题会让你「背答案」，一旦被深挖就露馅——**背答案比没准备更扣分**。

> **第一性结论**：存「原理 + 模式 + 反模式 + 人设状态」，不存「题目」。这是整个框架的基石。

---

## 2. 知识内核原子单位

最小、不可再分、可复用的知识颗粒 = 一条：

```
原子单位 = 原理 + 模式 + 反模式 + 人设状态
```

- **原理**：该维度下面试官到底想验证什么（来自 §1.2）。
- **模式（GOOD）**：高分表现长什么样；**反模式（BAD）**：低分表现长什么样。两者都来自真实记录，不是凭空编。
- **反模式·负知识**：哪些「看起来该准备、其实面不到」的题 → 进否决层当防火墙（见 §3 L5）。
- **人设状态**：候选人稳定的个人弱点当前处于「升级 / 稳定 / 降级」哪一档，驱动准备方向。

**示例（来自真实复盘）**：
> 面试官问"这个 95% 怎么得出的" → 不存"这道题"，存原子单位：  
> `维度=数据口径 | 原理=数字必须能答出口径/样本/对比基准 | 模式(BAD)=数字经不起追问 | 人设=B`

---

## 3. L0–L5 分层知识架构

知识按「原始 → 萃取 → 原理 → 模式 → 人设 → 否决」六层沉淀，越往下越抽象、越可复用。

| 层 | 名称 | 内容 | 规则 |
|----|------|------|------|
| **L0** | 原始层 | 每次面试逐字稿 / 复盘原文 | append-only，**永不删** |
| **L1** | 萃取层 | 统一 schema：`dimension / 真实问法 / 考察意图 / 我的表现 / 反馈 / 模式标签 / 人设标签 / 预测命中` | 结构化抽取，保留原话 |
| **L2** | 原理层 | 5 维度不变骨架，只增厚不增维 | 抽象原则 |
| **L3** | 模式层 | GOOD / BAD 正反案例库 | 标杆 + 自身正反经验 |
| **L4** | 人设层 | 个人弱点状态机（见 §6） | 可升级可降级 |
| **L5** | 否决层 | 「面不到的问题」= 负知识防火墙 | 收割过度预测，防退化 |

> **关键纪律**：L2/L3 只存维度与模式，**禁存标准答案**；L5 持续收割"预测偏了"的题。

---

## 4. 未知题四步拆解法（临场必走）

遇到没准备过的题，不要慌，按四步拆解：

1. **定位维度**：它考 5 维里的哪一个？（§1.2）
2. **还原意图**：面试官真正想验证什么——不是听答案，是看思考方式。
3. **调用模块**：从 §5 模块库取武器。
4. **结构化输出**：「总—分—总」金字塔（先结论塔尖 → 1–2 案例塔身 → 扣回岗位塔基）。

> 强制「开口前停 3 秒 + 结论先行」，直接治 C 类（语速快 / 逻辑散）问题。

## 5. 思维模块库（武器库）

| 模块 | 用途 | 何时用 |
|------|------|--------|
| **功能点聚焦法** | 被问"为什么做这功能"时砍枝节、只讲核心假设与场景 | 产品分析 / 设计题 |
| **数据口径七要素** | 任何数字必答：分子/分母/样本/周期/对比基准/定义/归因 | 一切带指标的回答 |
| **框架先行法** | 开放题先框定范围/目标再给方案 | 情景 / 开放设计题 |
| **展现态心法** | 场景化表达（谁+场景+问题+结果），不用空话 | 所有回答，尤其防"官方" |
| **1 页业务速览** | 面试前速览：商业模式/用户任务/技术架构/核心指标/竞品 | 投前必做（防 F 类） |
| **真实可验证迁移** | 跨专业/跨行业经历用"真实参与过的决策"迁移，不编造 | 动机 / 匹配题 |
| **五层拆透法** | 陌生产品/公司按 商业→用户→技术→模型→基础 逐层还原 | 业务速览 / 竞品分析 |
| **第一性原理应用** | 创新/颠覆题：回归本质需求→挑战约束→逻辑重构→落地到具体行为 | 产品创新 / 反问 |
| **STAR 第一性原理版** | 行为题讲"如何质疑根本假设、重新定义边界"，非"流程优化" | 行为 / 挑战题 |
| **定向自我介绍钩子** | 基于岗位 JD / HR 沟通 / 公开信息，先输出岗位理解，再用经历证明匹配 | 自我介绍 / 动机题 |
| **简历八大维度法** | 项目深挖按 背景→目标→动作→结果→指标→最大难点→权衡→再来一次 准备 | 简历面 / 项目深挖 |
| **业务链路拆解法** | 开放业务题按链路（拉新/促活/留存/转化/自传播）或视角/阶段切分，先框范围再下结论 | 业务面 / 开放题 |
| **过程指标异动拆解法** | 数据异动：先确认真问题 → 拆公式 → 看分子分母/同比环比/实际数值 | 数据口径 / 指标题 |
| **决策固定句式法** | 所有 why / 方案比较题用「在xx场景下，由于xx约束，所以xx更优」 | 逻辑表达 / 决策题 |
| **最大难点 / Plan C 法** | 最大难点 = 资源不足或目标未对齐；优先讲 Plan C 双赢，其次讲妥协轮次 | 项目深挖 / 挑战题 |
| **业务理解双轴法** | 面试中直接讲清"自己实习业务"（商业/用户/业务线/指标/竞品）+"面试公司业务"（1页速览）；既是准备也是临场表达 | 项目深挖 / 业务题 / 动机题（见 `业务理解双轴模块.md`） |

## 6. 人设状态机（个性化弱点，模板化）

人设弱点用「状态机」管理：每条弱点有 `升级 / 稳定 / 降级` 三态，由真实面试复现情况驱动转移。

### 6.1 通用弱点分类（可按候选人实际校准，不必全有）

| 代号 | 典型表现 | 触发场景 |
|------|----------|----------|
| **A** | 决策深度不足 / 经历边界感易被质疑（讲项目停在执行层，讲不清"为什么这样决策"） | 项目深挖 |
| **B** | 数据口径经不起追问（数字无分子/分母/样本/基准） | 一切带指标回答 |
| **C** | 表达语速快、逻辑散 | 所有回答 |
| **D** | 回答很官方、不接地气（套话多、无业务体感） | 谈专业 / 行业时 |
| **E** | 专业 / 经历迁移牵强（硬扯弱关联） | 动机 / 匹配题 |
| **F** | 对目标岗位业务了解不足（投前没研究公司/业务线） | 业务 / 动机题 |

### 6.2 校准规则（重要）

- 人设标签**必须用最新简历 + 候选人自我反馈对照**；
- 若候选人明确否认某标签，**降级为「历史风险」并改用更精确描述，禁止强行贴标签**；
- 简历图片/模糊材料不可读时，**必须要求文字版或高清原图**，禁止基于不完整信息下结论。

---

## 7. 三防火墙（防框架退化成押题）

1. **存原理不存题目**：L2/L3 只存维度与模式，禁存"标准答案"。
2. **L5 持续收割过度预测**：每次"预测偏了 / 面不到"都回流否决层。
3. **人设状态机驱动方向**：准备重点由 A–F 状态决定，而非题量。

## 8. 反哺流水线（让框架长大）

每次你给我**新材料**，按类型走不同入口：

### 8.1 输入类型 A：你的真实面试记录 / 复盘

```
新面试记录 → L0 落库(永不删) → L1 萃取(打维度/人设标签)
→ L4 更新人设状态机 → L3 写/更新模式(GOOD或BAD)
→ L5 预测偏差回流(面不到的题入否决层) → 版本号+1 → 生成「反哺 diff」
```

反哺 diff 给你说明：本次新增哪些证据、哪些维度被验证、哪条人设问题复现、预测命中率变化。

### 8.2 输入类型 B：面试经验库（他人 / 标杆案例 / 外部资料）

> ⚠️ **关键区分**：经验库**不是你自己的面试记录**，它是外部参考素材。

- 它**不进 L0/L1**（L0/L1 只存你本人的真实经历）；
- 它**进 L3 模式层**，作为 GOOD / BAD 标杆案例补充（如"某候选人强表现的可复制动作""某压力面的 red flag"）；
- 经验库中可提取的「通用方法论 / 思维框架」可升级进 L2 原理层或 §5 模块库；
- 经验库中的「具体题目」**不进 L5 否决层**，也不作为押题依据——只取其背后的原理与模式。

### 8.3 输入类型 C：新 JD / 目标岗位

- 触发 §10 使用协议中的「岗位准备流程」：JD 拆解 → 业务速览 → 人设风险映射 → 模拟题生成。

---

## 9. 红线

- **不编造答案 / 数据**：陌生领域承认边界 + 类比 + 秀方法论，而非编。
- **隐私优先**：简历 / 面试记录本地处理，云端模型仅作提质 Judge，Key 不落盘明文。
- **原话保留**：诊断 / 复盘 100% 保留用户原话（语气词、口误、不完整句都不改）。
- **评估类输出**走 LLM-as-Judge + rubric 行为锚定 + 偏见缓解 + 人标校准子集，禁用二元 rubric。

## 10. 使用协议（给你新材料时怎么用）

| 你给我 | 我做什么 | 产出 |
|--------|----------|------|
| **一份 JD + "帮我准备"** | JD 拆解 → 业务速览 → 5 维映射 → A–F 风险雷达 → 重点深挖方向 → 模拟题 | 岗位面试准备方案 |
| **一段真实面试记录/复盘** | 走 §8.1 反哺流水线 + 反哺 diff | 知识库更新 + 你的人设状态变化 |
| **一份面试经验库** | 走 §8.2：提取 GOOD/BAD 模式进 L3、方法论进 L2/§5 | 模式层增厚（不押题） |
| **"帮我模拟面试"** | 按目标岗位 + A–F 风险 + 数据口径坑，用真实考官语气出深挖题 | 模拟题合集 / 对话剧本 |
| **你的简历（文字/高清图）** | 结构化 + 数据口径卡 + 人设校准 | 人设/口径事实源 |
