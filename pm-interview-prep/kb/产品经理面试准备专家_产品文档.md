## 1. 背景与问题诊断（第一性原理）

### 1.1 现象：押题式备考的困境
用户此前用过「预测 25 题 / 5 维度」的方式备考，但实际面试复盘发现：**大量预测题根本面不到**（SQL DDL、RTA/RTB/oCPX、Widget 实现、主题商城商业化等），而真正被追问的是项目真实性、数据口径、业务理解——这些是预测覆盖不到的。

### 1.2 第一性原理追问：面试到底在考什么？
逐层下钻：
- 面试官**不是**在考「你背了多少标准答案」。
- 面试官**是在考**「你如何思考」+「你是否真实参与过」+「你的潜力与岗位匹配度」。
- 进一步下钻到物理本质：一次面试只有 30–60 分钟，面试官的信息带宽极小，他只能靠**少量高信号样本**推测你的底层素质。

> 佐证：资料 #2（人人都是产品经理·面试官视角）明确指出，面试官通过「同理心 / 洞察力 / 本质思维（第一性原理）」识别天赋，并强调「能把自己经验、能力、思考讲明白、逻辑清晰、让人一听就点头」的人才是可虑之选。资料 #9（今日头条·AI PM 面试开篇）直言：**「面试最终考的不是你背了多少答案，而是你是否建立了一套经过真实场景验证的认知体系。」**

### 1.3 错误的抽象层 vs 正确的抽象层
- ❌ **错误抽象（押题）**：存储原子单位 = 「题目」。题目发散无穷、维护成本爆炸、换一家公司/赛道就失效。
- ✅ **正确抽象（建结构）**：存储原子单位 = 「原理 + 模式 + 反模式 + 人设状态」。维度收敛（5 个），每次经验只是增厚证据厚度，不新增题目数量。

### 1.4 结论
系统的目标**不是**预测更多题，而是把每次面试经验沉淀为可复用的「能力维度 → 思维模块 → 反模式防火墙」，并能反哺成长。这与用户已完成的架构设计完全一致，本 PRD 将其落到可执行的产品细节。

## 2. 产品目标与第一性原理假设

### 2.1 北极星指标
**「单次面试准备时效」×「人设状态机覆盖率」**——更直白地说：
- 上传一场新面试 → 系统在 N 分钟内给出「反哺 diff」（哪些维度被验证、哪些人设问题复现、预测偏差多少）。
- 面试官问到未知题时，用户能在 30 秒内走完「定位维度 → 结构化输出」并开口。

### 2.2 核心假设（底层逻辑，须产品全程守护）
1. **能力维度收敛**：实习生 PM 面试只考 5 件事——项目真实性 / 产品思维 / 逻辑表达 / 动机匹配 / 学习能力。
2. **模式可迁移**：GOOD 案例的行为（数据口径透明、场景化表达）与 BAD 案例的反模式（反复追问结果、隐瞒 gap）跨公司普适。
3. **人设状态可量化**：用户的 6 个问题 A–F 是状态机，能升级也能降级，驱动准备方向。
4. **负知识有价值**：明确「面不到的问题」是防火墙，防止系统退化成押题工具。

### 2.3 成功标准
- 知识库从 9 份记录（6 真实 + 3 标杆）增长到 N 份时，**预测题数不增长**，但「维度覆盖度」与「反模式命中率」提升。
- 用户下一轮真实面试中，A–F 人设问题复现次数逐场下降。

## 3. 用户与场景

### 3.1 目标用户画像
- 身份：产品经理实习生求职者（如用户本人，跨专业背景、有运营/数据经历、表达偏快偏官方）。
- 痛点：押题无效、被追问数据口径会慌、表达散/官方、对目标岗位业务了解不足。
- 目标：用最小精力建立可复用的面试认知体系，而非刷更多题。

### 3.2 典型场景
| 场景 | 触发 | 系统行为 |
|---|---|---|
| S1 上传新面试 | 用户丢入一份面试记录/复盘 | 解析 → 打维度标签 → 更新人设状态机 → 写模式库 → 预测偏差回流否决层 |
| S2 临场未知题 | 面试官问了没准备过的题 | 调出「结构化思维框架四步 + 模块库」给出拆解路径 |
| S3 复盘自查 | 面试结束即时复盘 | 套用「固定三块」复盘模板，产出可检索档案 |
| S4 岗位速览 | 面试前准备某家公司 | 生成 1 页「业务速览」（商业模式/用户任务/技术架构/核心指标） |

> 佐证：资料 #7（单面终极指南）强调「即时复盘 + 个人面试档案库」是闭环关键；资料 #4（AI PM 复盘双库）证明了「把工作流程当产品来做」的杠杆。

## 4. 可扩展知识结构（让每次经验反哺成长）

### 4.1 六层存储模型 L0–L5
- **L0 原始层**（append-only 证据底座，永不删）：每次面试的逐字稿/复盘原文。
- **L1 萃取层**（统一 schema）：dimension / 真实问法 / 考察意图 / 我的表现 / 反馈 / 模式标签 / 人设标签 / 预测命中。
- **L2 原理层**（5 维度不变骨架，只增厚不增维）。
- **L3 模式层**（GOOD/BAD 正反案例库）。
- **L4 人设层**（A–F 状态机，可升级可降级）。
- **L5 否决层**（「面不到的问题」= 负知识防火墙）。

> 佐证：资料 #4（AI PM 复盘双库）作者连面 6 家后沉淀「题库 + 项目素材库」双库结构，并特别指出「复盘的结构化远比复盘的勤奋度重要——每场 800 字但固定三块，复利是 2000 字的十倍」。这正是 L0–L5 与统一 schema 的实证来源。

### 4.2 反哺流水线（端到端）
```
新面试记录 → L0 入库 → L1 萃取(打维度/人设标签) → L4 更新人设状态机
→ L3 写/更新模式(GOOD或BAD) → L5 预测偏差回流(面不到的题入否决层)
→ 版本号 +1 → 生成「反哺 diff」给用户
```

### 4.3 双库结构（借鉴资料 #4）
- **题库（模式库）**：存「维度 + 考察意图 + 高分回答骨架」，不存标准答案。
- **项目素材库**：用户自己的项目，每个项目挂「数据口径卡 + 决策细节卡」，受控删除（二次确认），避免误删。

### 4.4 资料佐证小结
- 知识结构的可扩展性与反哺理念：资料 #4（双库 + 结构化复盘）。
- 维度收敛的合理性：资料 #2（面试官只看本质思维/洞察/同理心）、资料 #9（考认知体系非答案）。
- 否决层的必要性：用户真实复盘已证明大量预测题面不到（见蒸馏库 v3「面不到问题」审计表）。

## 5. 结构化思维框架（未知问题快速拆解）

### 5.1 通用拆解法四步（所有未知题通用）
1. **定位维度**：这是 5 维里的哪一维？（项目真实性 / 产品思维 / 逻辑表达 / 动机匹配 / 学习能力）
2. **还原意图**：面试官真正想验证什么？（不是听答案，是看思考方式——资料 #2、#9）
3. **调用模块**：从模块库取对应武器。
4. **结构化输出**：遵循「总—分—总」金字塔（资料 #7：先结论塔尖，再 1–2 案例塔身，最后扣回岗位塔基）。

### 5.2 可复用模块库
| 模块 | 用途 | 来源 |
|---|---|---|
| 功能点聚焦法 | 被问「为什么做这个功能」时，砍掉枝节、只讲核心假设 | 用户蒸馏库 |
| 数据口径五要素 | 任何数字必须能答：口径 / 样本 / 对比基准 / 归因 / 置信度 | 用户蒸馏库 + 资料 #1（被「95% 怎么得出」追问的教训） |
| 框架先行法 | 开放题先框定范围/目标，再给方案 | 资料 #10（产品设计高分策略） |
| 展现态心法 | 场景化表达（用具体反例，而非空谈能力） | 用户蒸馏库 + 标杆 GOOD |
| 1 页业务速览 | 面试前速览目标公司商业模式/用户任务/技术架构/指标 | 用户蒸馏库 + 资料 #8（五层拆透法） |
| 真实可验证迁移 | 跨专业经历用「真实参与过的决策」迁移，不编造 | 用户蒸馏库 |
| **五层拆透法** | 陌生产品/案例按「商业→用户→技术→模型→基础」逐层还原决策，而非列功能清单 | **资料 #8** |
| **第一性原理应用** | 创新/颠覆题用「回归本质需求→挑战技术约束→逻辑重构方案」，并立刻落地到软件行为，避开「哲学陷阱」 | **资料 #3**（浏览器案例） |
| **STAR 第一性原理版** | 行为题讲「如何质疑根本假设、重新定义边界」，而非「流程优化」 | **资料 #5（Tesla）/ #6（OpenAI）** |

> 关键：资料 #3 警示「哲学陷阱」——提到第一性原理时，必须迅速落地到具体软件行为（如「剥离地址栏/前进后退等历史形态，思考信息流动最小单位」），不能背马斯克火箭。资料 #5 更直白：**面试官找的是「解决方案设计师」，不是「需求收集者」**；资料 #6 强调在模糊未知中「创建流程而非遵循流程」。

### 5.3 陌生领域应对策略
当被问到完全不了解的业务（如用户曾被 BIGO 问 DSP 而不知）：
- 承认边界（不编造）；
- 用已知结构类比（五层拆透法中的「用户任务」层是通用的）；
- 秀方法论（「我会先拉 X 数据、按 Y 维度拆解」）而非编答案。
> 佐证：资料 #8 的「五层拆透法」本身就是为「一个下午拆透完全陌生的 AI 产品」设计的；资料 #10 的「维度拆解 + 假设驱动」也是无数据时的通用路径。

## 6. 自我评估与迭代机制

### 6.1 复盘模板（固定三块，来自资料 #4 + 资料 #7）
每场面试结束即时写 800 字，固定结构：
1. **被问到的问题 + 我的回答要点**（原话保留，不润色——资料 #4 红线：诊断必须 100% 保留原话）；
2. **面试官反应 + 我好/不好的地方**（意图—表达 Gap 分析）；
3. **新信息 + 下一轮行动**（回流人设状态机与选项）。

### 6.2 量化看板
| 指标 | 含义 | 驱动动作 |
|---|---|---|
| 维度覆盖度 | 5 维各被多少真实记录验证 | 覆盖低的维多补真实案例 |
| 人设状态分布 | A–F 各自处于升级/稳定/降级 | 状态降级→优先准备 |
| 预测命中率 | 预测题实际出现比例 | 持续低→收割进否决层 |
| 模式库规模 | GOOD/BAD 案例数 | 厚度指标 |
| 案例数 | L0 原始记录数 | 成长性指标 |

### 6.3 触发规则（三类自动演化）
- **降级规则**：某预测题连续 N 场未出现 → 降入 L5 否决层。
- **升维规则**：某维度 ≥2 场重复出现且无子维度 → 在 L2 增厚子维度。
- **人设升级规则**：某 A–F 问题在真实面试中再现 → 状态机升级并触发对应准备模块。

### 6.4 衰减护栏（三防火墙，防退化成押题）
1. **存原理不存题目**：L2/L3 只存维度与模式，禁存「标准答案」。
2. **L5 持续收割过度预测**：每次预测偏差都回流否决层。
3. **人设状态机驱动方向**：准备重点由 A–F 状态决定，而非题量。

> 佐证：资料 #1（90% 坑，2026/07/09）明示复盘要从「心态/项目/视野/规划/沟通/复盘」六面入手，且项目介绍必须「真实、用 STAR、能经得起追问」——直接支撑 6.1 与 L5 真实性维度。资料 #7 的「即时复盘 + 感谢信 + 个人档案库」闭环是 6.1 的来源。

## 7. 信息架构与数据流

### 7.1 系统模块
```
[输入] 面试记录/复盘 → [解析器] 打标签(schema) → [L0-L5 存储]
                                            ↓
[思维框架引擎] ← 模块库 ← [L2/L3]
     ↑                          ↓
[人设状态机] ← [评估迭代引擎] ← 量化看板 + 触发规则
     ↓
[输出] 反哺 diff / 临场拆解路径 / 1页业务速览 / 复盘模板
```

### 7.2 一次面试如何反哺（端到端）
1. 用户上传逐字稿 → L0 落库（永不删）。
2. 解析器抽取 L1 字段，自动标注 dimension + 人设标签。
3. 若命中 A–F 某问题 → L4 状态机升级/降级。
4. 若行为匹配 GOOD/BAD 模式 → L3 写/更新。
5. 若某预测题未出现但有类似 → L5 收割。
6. 版本 +1，生成「反哺 diff」给用户，提示「本次新增 X 证据、Y 维度被验证、Z 人设问题复现」。

## 8. 验收标准

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 可扩展 | 新增 1 份面试记录，系统能在不新增「题目」的前提下完成 L0–L5 全流程反哺 |
| AC2 | 可拆解 | 给定一道用户未准备过的面试题，系统能在 30 秒内输出「定位维度→还原意图→调用模块→总分层输出」路径 |
| AC3 | 可迭代 | 连续 3 场某预测题未出现，系统自动将其降入 L5 否决层 |
| AC4 | 人设驱动 | A–F 状态机随真实面试升级/降级，并触发对应准备模块 |
| AC5 | 不退化 | 知识库增长时，预测「题目数」不增长，维度覆盖度与反模式命中率上升 |

## 9. 路线图（MVP → v2 → v3）

- **MVP（v0.1，本 PRD 落地）**：Skill 骨架 + 挂载蒸馏库 v3（L0–L5 已就绪）+ 触发词 + 反哺流水线脚本 + 思维框架四步 + 模块库 v1。
- **v2**：接入资料 #4 的「双库 + 受控删除」交互；复盘模板固定三块自动化；量化看板可视化。
- **v3**：每场面试可挂原始录音片段（资料 #4 未竟目标）；跨项目关键词自动索引；人设状态机与岗位 JD 自动对齐，生成 1 页业务速览。
