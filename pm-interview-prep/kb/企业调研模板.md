# 企业调研模板（业务素养 · T9/T5 调用）

> 用途：面试前（T9）或复盘时（T3）补充「公司业务素养」——查清楚公司身份、上市/融资、产品、规模、财务、展望，辅助准备与入职决策。
> 触发：用户给岗位/公司名即跑；尤其当产品形态未知、跨域岗（F 风险高）时必须跑。
> 第一性原理：业务了解不是"背公司介绍"，而是面试中直接被考的"现场讲业务 + 判断匹配"能力，且关乎"要不要去这家公司"的决策。

## 一、数据源优先级（逐级查，实在没有再降级）

> **★ AI 业务必查分则（v0.24 硬规则 · 零省略）**：查这家公司时**必须同时查其 AI 方向业务**，不得只查"公司简介/产品矩阵/财务"就出稿。查法：官网 AI 频道 / AI 相关新闻 / 招聘 JD 里的 AI 岗位 / 技术博客 / 开源仓库。把"它用 AI 做了什么"单独成段写进 `索引_<公司>.md` 的「AI 业务认知」。**若该公司无公开 AI 动作**，不要跳过——切到**行业级 AI 应用认知兜底**：用 `kb/AI应用认知库_通用落点图谱.md` 的 6 落点框架（意图理解/属性结构化/内容生成/匹配排序/决策解释/异常识别）给"这个行业普遍怎么用 AI"的通用论断，并显式标「行业级兜底·非该公司专属」。理由：面试官现在普遍把"你知不知道我们/这行怎么用 AI"当现场考点硬门槛。

1. **工商信息**：爱企查 / 企查查 / 天眼查 → 成立时间、法人、注册资本、参保人数、企业类型（小微/集团）、上市状态、分支机构。
2. **百科 / 新闻 / 官网**：百度百科、公司官网、36氪、多知网、长江网、腾讯新闻 → 融资历程、产品矩阵、战略、关键人事。
3. **招聘 JD**：JobSpring / BOSS / 官网招聘 → 岗位职责即「岗位能力映射」，反向印证公司业务重点（如领格卓越 JD 明写"AI Prompt 体系 + 评测 + 文本/语音/图像数据闭环"）。
4. **榜单 / 行业**：GSV 150、Fast Company 全球最具创新力 → 行业地位与成长性。
5. **股市数据**：若已上市，查股票代码 / 财报 / 市值 / 近期股价（东方财富、雪球）；**若未上市，明确标注"私有公司 + 累计融资 X + 投资方"，不编造 IPO**。
6. **GitHub 兜底**（官方信息稀薄时）：查公司 GitHub Org / 技术博客 / 开源仓库，获取技术栈信号（如 AI 公司是否开源模型/工具）；**若无公开技术仓库，注明"未检索到公开技术仓库，技术信号以招聘 JD + 产品官网为主"**——绝不编造。
7. **中国特供源段（必读·GitHub 欧美工具对中国私企基本查不到）**：GitHub 上的企业调研开源工具（company-radar / companyscope-mcp / company-research-agent 等）数据源几乎全是欧美导向（OpenCorporates / SEC EDGAR / Companies House / Glassdoor / Blind），**对中国公司（领格卓越 / 货拉拉 / 趣丸等）基本取不到数据**。中国公司请改用以下特供源：
   - **工商**：天眼查 / 企查查 / 爱企查 → 上市状态、融资、分支机构、参保人数。
   - **资本市场**：港交所「披露易」（货拉拉递表）、上交所/深交所、东方财富/雪球（已上市）。
   - **雇主口碑**：看准网 / 脉脉 / 牛客 / 小红书 → 真实员工评价、加班、业务线现状。
   - **产品数据**：七麦数据 / 点点数据 → App 下载量、收入预估、版本节奏。
   - **新闻+JD**：36氪 / 多知网 / 公司官网 + BOSS/官网招聘 JD → 业务重点反向印证。
   - **GitHub 欧美工具的价值在「方法论+数据源清单范式」**，其架构（兜底数据源聚合、多节点拆解）可直接借鉴，但**不能直接跑出中国公司档案**。

## 一·B 调研结构：四路节点并行拆解（参考 company-research-agent）

> 不要线性平铺，按「业务 / 行业 / 财务 / 新闻」四路**并行**调研，再经「汇总 → 筛选 → 简报 → 编辑」四步收敛成 1 页速览。每路各回答一个核心问题：

1. **业务节点**：这公司靠什么产品/服务赚钱？面试岗在哪条业务线？（→ 喂给 §二.2 产品矩阵 + 索引「AI 子域常识兜底」）
2. **行业节点**：所在赛道规模、增速、竞品格局、政策壁垒？（→ 喂给 §二.5 展望 + F 业务了解）
3. **财务节点**：上市否、营收/融资/盈利、资本态度？（→ 喂给 §二.3 规模财务 + §二.4 股市资本）
4. **新闻节点**：近 6 个月大事、负面舆情、组织变动、战略转向？（→ 喂给 §二.5 展望 + 入职决策风险项）

- **收敛四步**：①汇总四路原始事实 → ②筛选与岗位/入职决策相关的信号 → ③写成 1 页速览简报 → ④编辑定稿（事实/推测分标）。
- 对应 GitHub 参考：`company-research-agent`（业务/行业/财务/新闻四节点 → 汇总/筛选/简报/编辑，1.9k★）、`companyscope-mcp`（一次聚合 12 个免费源，MIT）。

## 二、输出结构（1 页企业速览）

1. **公司身份与上市状态**：全名/英文名、创立时间、总部、是否上市（代码/估值/融资）、中国实体关系。
2. **产品矩阵与业务场景**：核心业务、新业务（尤其面试岗所在）、技术形态。
3. **业务规模与财务健康**：用户/课时/教师数、是否盈利、榜单。
4. **股市与资本视角**：上市否、股权流动性、政策风险。
5. **未来展望**：战略方向、新业务确定性。
6. **入职决策参考**（若用户关心）：用「绿旗/红旗 + 三档结论」格式输出（参考 company-radar 的 PURSUE/CAUTION/AVOID 范式）：
   - **绿旗（加分项）**：匹配你经历/成长/财务稳健等正面信号——标【事实】或【推测·待核实】。
   - **红旗（风险项）**：私有无股权流动性、教育/行业政策风险、新业务未验证、加班/组织变动负面舆情等——逐条标事实/推测。
   - **三档结论**：基于绿/红旗综合给 **PURSUE（建议去）/ CAUTION（谨慎、需进一步确认）/ AVOID（不建议）**，并写明触发该档的关键依据。
   - 红线：**只列利弊，最终是否去由用户定**；不替代用户判断。
7. **AI 业务认知（v0.24 必出段）**：查公司时同步查其 AI 方向业务后单独成段——①**该公司 AI 动作**（有则写实：官网 AI 频道/AI 新闻/AI 岗位/JD/技术博客/开源，具体做了什么、用在哪条业务链）；②**若无公开 AI 动作 → 行业级兜底**：用 `kb/AI应用认知库_通用落点图谱.md` 6 落点给"这个行业普遍怎么用 AI"的通用论断，标「行业级兜底·非该公司专属」。该段同时回填 `索引_<公司>.md` 的「AI 业务认知」+ 喂给 T9 逐字稿层的 AI×业务准备，违反则触发 §9 防火墙 #7。

## 三、红线

- **事实 vs 推测 分标**：公开可查标【事实】，推断标【推测·待核实】；融资/估值未披露不编。
- **隐私合规**：仅用公开信息，不抓个人数据。
- **不替代用户判断**：入职决策参考只列利弊，最终由用户定。
- **与 F 人设联动**：调研结果同时回填 `state_A-F.md` 的 F 维度（若补出产品形态/技术栈，降低 F 风险），并写入 `索引_<公司>.md`。

## 四、与 Skill 其他模块接线

- **T9 面试前准备**：本模板是第 1 步（给岗位→先调研公司），输出喂给 `索引_<公司>.md` 的「1 页业务速览」+「AI 子域常识兜底」。
- **T3 复盘**：§2 底层逻辑用调研结果判断"公司业务理解"是否到位；§5 准备动作引用本报告。
- **业务理解双轴模块（轴 B）**：本模板是轴 B「1 页速览」的数据供给方。
