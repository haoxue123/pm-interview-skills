# GitHub 参照蒸馏：面试系统架构

**版本**：v1.0  
**蒸馏对象**：
- `noamseg/interview-coach-skill`（1630★，fork 本体）
- `Snailclimb/interview-guide`（2843★）
**目的**：把高星项目里可复用的工程/方法论模式，迁移进本 Skill，补全状态持久化、storybank、adaptive drill 与 PDF 导出。

---

## 0. 为什么需要这次蒸馏

本 Skill 已解决的问题：
- 面试答案的第一性原理结构（STAR / 数据口径 / 决策边界）
- 业务理解双轴（讲清自己实习业务 + 面试公司业务）
- PDF 导出管线（见 `scripts/md2pdf.py`）

还缺的一层：**把每次面试准备变成可持续迭代的状态系统**。之前每轮准备都像是"重新来过"：没有个人 storybank，没有跨会话的薄弱项追踪，没有根据上次评分自动推送下一次练习。两个高星项目恰好补这一层。

## 1. noamseg/interview-coach-skill（1630★）可迁移设计

### 1.1 持久化状态：`coaching_state.md`
跨会话自动维护一份状态文件，记录：
- storybank 清单
- 五维评分（如本 Skill 的 A–F 人设）
- 行为模式 / 最近瓶颈
- 练习进度、真实面试结果、面试轮次

**迁移做法**：把 A–F 人设状态机从"一次性生成"升级为"文件级状态"。每次对话后把关键发现写回 `kb/状态机_<姓名>.md`，下次触发先读此文件，再问"上次卡在哪"。

### 1.2 Storybank：结构化故事库
每个故事存：
- 完整 STAR 文本
- earned secrets（独家洞见）
- 强度评级
- 最近使用日期
- 4 级匹配分：Strong Fit / Workable / Stretch / Gap

**迁移做法**：新增 `kb/storybank_项目故事库.md`，把百度/字节/作业帮三段经历写成可复用故事卡片。面试题来了先做"题—故事匹配"，再组合优化，避免同一项目被反复用。

### 1.3 Adaptive Drill：按瓶颈自动选练习
评分后由决策树分流：
- Relevance 弱 → 题目解码练习
- Substance 弱 → 补原始素材
- 含 8 阶进阶（约束梯、反驳、pivot 等）

**迁移做法**：把 T1–T5 任务剧本升级为"评分→诊断→推送"闭环。例如用户讲完项目被打 C，Skill 不再泛泛给建议，而是直接命中"数据口径不足"并推送 T3 数据口径审计。

### 1.4 工作流：kickoff → decode → prep → practice → analyze
| 阶段 | 对应本 Skill |
|---|---|
| kickoff 建档 | 上传简历 + 建立 A–F 状态 |
| decode 解析 JD | 岗位画像 / 业务速览 / 风险点 |
| prep 定制简报 | 生成公司专属准备方案 |
| practice/mock | 模拟面试 / 追问深挖 |
| analyze/debrief | 上传面试记录 → 更新状态机 |

## 2. Snailclimb/interview-guide（2843★）可迁移设计

### 2.1 知识库分层
- 文档上传 → 分块 → 向量化（pgvector）→ RAG 检索
- 题库按方向/难度生成
- 专项面试抽题评估

**迁移做法**：目前 kb/ 是按"模块"组织（原理、方法、案例）。可增设按"岗位/公司/题型"的二级索引，例如 `索引_高仙.md`、`索引_商业化产品_一面.md`，让用户快速定位。

### 2.2 机制支持
- **面试题导航**：Skill 驱动出题，10+ 方向
- **时间规划**：面试安排 + 日历视图
- **PDF 导出**：简历/面试报告一键导出
- **自测雷达**：评估报告含优势/改进建议、表现趋势

**迁移做法**：
- PDF 导出：已用 `scripts/md2pdf.py` 落地，下一步把"模拟面试评估报告"也接到管线上。
- 自测雷达：在 A–F 状态机基础上出可视化雷达图（可调用 chart/image 工具），追踪历次面试的弱点变化。
