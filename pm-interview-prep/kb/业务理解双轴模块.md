# 业务理解双轴模块（第一性原理 · 面试中"讲业务"的显性化）

> 版本：v1.1 · 新增于 2026-07-27（候选人提出 Skill 缺少"业务讲解"模块，覆盖实习公司业务 + 面试公司业务双轴）；v1.1 于 2026-09-23 增补 §3「内外坐标提问法」（用户提供素材：对外看竞品/区别/护城河，对内看协同部门/核心考核指标/双向互利）
> 配套：第一性原理框架 §5 模块库、人设 A/F 应对
> 第一性原理：业务讲解不是"准备清单"，而是面试中直接被考的"表现动作"。它同时服务两个信号维度——讲清自己实习业务 = 验证项目真实性/产品思维；讲清面试公司业务 = 验证动机与匹配。
>
> **本文件有两套互不冲突的切法，别混用**：
> - 轴 A / 轴 B = 切**来源**（讲哪家公司的业务：自己实习的 / 面试目标公司的）
> - §3 内外坐标 = 切**方向**（从哪两个方向把业务切开：向外看竞争 / 向内看协作）
> 两者正交，可叠加。**优先把 §3 用在轴 A**（自己待过的业务），因为对内四问只有真待过才答得实。

## 1. 为什么 Skill 初期缺这块（根因）

Skill 的设计起点是"5 维度信号"。业务理解被拆进了两个维度，但没有独立成模块：

- **自己实习公司的业务**：Skill 假设"你做过项目自然懂业务"，于是把它隐含在"项目真实性"维度，用数据口径卡 + 决策细节卡覆盖。但真实面试证明不是——BIGO 直接问"百家号变现模式是什么""创作者在你们平台怎么变现""收入最高的三个方式"，这是**业务知识**，不是项目执行细节。
- **面试目标公司的业务**：Skill 有"业务速览"概念，但只作为人设 F 的"防御清单"（投前填一下），没有展开成"面试中怎么讲/怎么展现"的操作模块。

**根因一句话**：Skill 初期把业务理解当成"准备动作"，但真实面试（高驰要你讲具体功能好坏、BIGO 要你讲百家号变现）会直接考你"现场讲业务"。所以它既是准备，也是临场表达，必须独立成模块。

## 2. 双轴方法

### 轴 A：讲清自己实习公司的业务（验证"我真的懂我做的业务"）

目的：让面试官相信你是"懂业务的产品人"，不是只会跟进执行（直接对冲人设 A"偏运营/决策浅"）。

五个必答点（每段的实习都要备）：
1. **商业模式**：这个业务/产品线怎么赚钱？（如百家号 = 广告分成 + 内容电商 + 付费专栏）
2. **用户任务**：核心用户（创作者/广告主）在你的平台怎么完成他的任务？
3. **业务线定位**：你所在的岗位/项目处于价值链哪一段？（如百度分润周结 = 创作者变现链路的"结算"环节）
4. **核心指标口径**：你项目的上游/下游指标是什么？你的动作影响哪一段？（用数据口径卡）
5. **竞品参照**：这个业务的直接竞品是谁？（如百家号 vs 抖音/快手/小红书）

**候选人实例（P0 必补）**：
- 百度百家号：创作者变现方式（商单/分成/补贴）；收入前三方式排序；月结 30 天为什么限制 MCN 周转和中小作者留存（即你项目的业务根因）。
- 字节星搜：搜索品专商业模式；广告主 ROI 诉求；样式屏占比低的业务影响。
- 作业帮：直播电商带货链路（流量 → 直播间 → 转化 → 售后）；你运营的店铺在链路哪段。

### 轴 B：讲清面试目标公司的业务（验证"我研究过、我匹配"）

目的：证明你投前做了功课，直接对冲人设 F。

1 页业务速览模板（投前必填）：
1. 公司商业模式（靠什么赚钱）
2. 岗位所在业务线（你进去做哪块）
3. 核心产品 / 客户 / 指标
4. 3 个竞品

**候选人翻车对照**：
- BIGO：不知道是 DSP 效果广告，不懂 DSP/SSP/ADX → F 高风险。
- 雅迪：两轮车智能化理解偏浅 → F 中风险。
- 改进：每次投前填 1 页速览，面试开场自我介绍/动机题直接调用。

### 轴 B 增补（v0.8 · 领格卓越一面验证）：未知产品 → 强制备 AI 子域常识兜底

当 HR/公开信息只说"做 AI 产品"、产品形态未知时（领格卓越正是这种情况），**不能只写"信息缺口待补"就结束**，必须强制备 3–4 个 AI 子域的"我了解多少 + 怎么学"话术，作为兜底弹药：

- **对话 / 语音 agent**（最高频）：技术栈 ASR → NLU/对话管理(DM) → NLU → NLG → TTS；难点在多轮状态一致性、个性化回复。领格卓越产品本质=AI 老师（对话 agent），事前零储备导致被问"了解语音 agent 吗"只能说"不会" → 直接撞产品核心技术，F 风险拉满。
- **多模态**：文本/图像/语音跨模态对齐与生成。
- **RAG（检索增强生成）**：外部知识库检索 + 生成，缓解幻觉。
- **内容生成 / AIGC**：文本/图像/视频自动化生产。

**话术底线（别再说"完全不会"）**：即使只到"我知道它由 X 几层组成、难点在多轮一致性，我目前主要实践在 prompt 工程和工作流搭建，正在补技术栈"也够——展示"有框架认知 + 诚实 + 学习路径"，而非空白。

## 3. 内外坐标提问法（对外 / 对内 · v1.1 新增 2026-09-23）

> **素材来源**：用户提供的培训素材原话——"在实习的时候，对外：需要了解竞品有哪些，你方公司和竞品的区别是什么、护城河是什么；对内：要了解你的协同部门有哪些，他们天天在做什么，他们的核心考核指标是什么，你做什么事情能够更好提升他们的考核指标，以及，他们通过什么事情能更好完成他们的考核指标。"
>
> 本节把它从"一句话提醒"提炼成**可直接跑的三段提示词 + 一张填写纪律表**，让每次准备都能落地成答案，而不只是"记得去了解"。

### 3.1 第一性原理（为什么恰好是这两个方向）

业务理解的目的不是背事实，是**给你的工作定位**。一个岗位的定位，只可能由两件事决定：

- **向外**：这门生意能不能活，由**竞争**决定。所以你得知道自己站在哪张牌桌上、凭什么叫用户选你、别人为什么抄不走。
- **向内**：你的产出有没有价值，由**谁消费**决定。所以你得知道下游被什么数字压着、你替他们省了什么、他们能给你什么。

两边交叉，你的工作就从"一个功能"变成"一个活下来的生意里、替某个人完成他的指标"。这正是面试官问"你怎么理解我们业务"时真正想听的。

> 一句话：**对外判生死，对内判价值。**

### 3.2 提示词（三段，可直接复制使用）

**Prompt A · 对外三问（竞争坐标）**

```
请帮我把【公司 / 业务线】按竞争坐标拆成三问，逐条给答案，并标注来源（事实 / 推测 / 待查）：
1. 竞品有哪些？分两层：直接竞品（做同一件事的）、间接竞品（用别的方式解决同一需求的）。
2. 我们和竞品的区别是什么？不要停在功能对比，必须落到"用户为什么选我们、不选他们"。
3. 我们的护城河是什么？回答"别人要抄走，最难的卡在哪一步"，从这几类里选：供应 / 数据 / 网络效应 / 成本 / 品牌 / 牌照 / 切换成本。
每条答案末尾补一行「面试怎么用：这题能接哪类问题」。
查不到的写"待查"，不要编。
```

**Prompt B · 对内四问（协作坐标）**

```
请帮我把【公司 / 部门 / 我的岗位】按协作坐标拆成四问，逐条给答案，并标注来源（事实 / 推测 / 待问）：
1. 我的协同部门有哪些？按链路列：上游（给我输入的）、下游（消费我产出的）、并行（配合我的）。
2. 他们天天在做什么？每个部门一句话，说你听得懂的大白话。
3. 他们的核心考核指标是什么？每个部门给 1–2 个可计算的数字。
4. 双向互利：我做什么事能提升他们的指标？他们做什么事能帮我完成我的指标？
   —— 第 4 问是重点。必须给出"我的动作 → 他的指标"的因果链，禁止用"加强沟通""积极配合"这类空话收口。
每条答案末尾补一行「面试怎么用：这题能接哪类问题」。
```

**Prompt C · 收口句（把七问压成一句定位）**

```
用一句话把我的工作定位说清楚，句式：
"我在【业务】里负责【环节】，对外靠【区别 / 护城河】赢过【竞品】，对内替【协同方】完成【他的指标】。"
要求：主语清楚、短句、不出现"赋能""闭环""抓手"这类词。
```

### 3.3 填写纪律（四条，违反则答案作废）

| 纪律 | 内容 |
|---|---|
| **① 对内四问只对"自己待过的业务"要求答实** | 面目标公司时，第 3、4 问基本只能推测 → 必须标「推测」，并**转成反问抛给面试官**（"你们这个项目的核心指标是看消耗还是看留存？"），不要当结论说 |
| **② 第 4 问是分水岭** | 只会背"协同部门有财务、风控、算法"的人，和能说出"我把周结从 30 天压到 7 天，抬的是创作者运营的留存、顺带解的是 MCN 渠道的周转"的人，是两个段位。第 4 问答不出来的业务，等于没懂 |
| **③ 对外第 3 问不许答"我们产品体验好"** | 护城河 = **别人抄走时最卡的那一步**。答不出具体卡点，就说明你只知道功能，不知道生意 |
| **④ 收口禁空话** | 撞人设 D（很官方）红线。七问答完必须能说出 Prompt C 那句定位句，说不出来就是还没答完 |

### 3.4 对内四问的答案不预填（2026-09-25 用户定）

> **本模块不提供任何"填法示例 / 标准答案表"。** 用户判断：**具体业务（协同部门是谁、他们考核什么指标、我怎么影响他的指标）只能由面试官当面讲解**。从岗位逻辑"推"出来的答案一律是脑补，拿去面试就是虚报。2026-09-25 已据此删掉初版的「三段实习填法示意表」。

正确使用姿势：

- **准备阶段**：对内四问是**要问的问题清单**，不是要背的答案。写成反问抛给面试官——"这个岗进来主要和哪几个团队配合？他们被什么指标考核？"。
- **复盘阶段**：面完或实习结束后，把当次真实拿到的协同方、考核口径、因果链**沉淀进该场的复盘文档**（`复盘标准模板.md`）或 `索引_<公司>.md`。
- **技能层只存提问框架，不存各公司的业务细节。** 有人试图往这里写"某公司的协同部门是 X"——不要写，那是复盘的事。

## 4. 临场"讲业务"话术结构（总分总 + 场景化）

**反问后回扣匹配（v0.8 新增 · 领格卓越一面验证）**：当你通过反问得知产品形态后，**立刻用 1 句回扣你的匹配资产**，别让信息停在"我了解了"。
> 例：领格卓越反问挖出产品=AI 老师（自动化链路），应接"这个自动化链路正是我字节搭 AI 提案 workflow 的能力，我能直接上手"——当场把产品了解转化为匹配证据。漏掉这步 = 白挖了产品形态。

被问"你们业务怎么变现 / 这个业务为什么这样设计"时：

> 结论先行："我们这条业务主要靠 X 变现。"
> 展开："核心用户是 Y，他在我们平台完成 Z 任务；我负责的是其中的 [业务线定位] 这一段。"
> 落地："比如我做的分润周结，解决的正是中小作者因为月结 30 天导致资金周转慢、流失变高的问题——这就是商业模式的 [具体环节]。"
> 扣回："所以我的项目不是孤立功能，而是卡在变现链路的结算环节上。"

注意：用具体项目/数字落地，别空谈"价值交换/生态"（人设 D 红线）。

## 5. 与 A–F 人设映射

| 人设 | 本模块如何对冲 |
|------|--------------|
| A 决策深度/偏运营 | 轴 A 讲清业务线定位 + 价值链，证明你懂为什么做，不是只执行 |
| F 业务了解不足 | 轴 B 1 页速览，投前必做 |
| D 很官方 | 临场话术强制"用项目+数字落地"，禁宏大叙事 |
| A + F 同时高危场 | **§3 内外坐标**：对外第 2/3 问逼你说"为什么是我们"（不是功能层），对内第 4 问逼你说"我替谁完成什么指标"（不是执行层）。这两问答得实，A 与 F 同时降级 |
